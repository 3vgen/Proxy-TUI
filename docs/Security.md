# Безопасность

## Пароль sudo
- Хранится в `~/.sudo_password` (владелец `evgeniy`, chmod `600`).
- Используется скриптами и CLI через `echo "$pass" | sudo -S …` — чтобы агенты работали без интерактивного ввода.
- ⚠️ Пароль запрашивался пользователем **явно** и преднамеренно для совместной работы агентов. Правила:
  - не выводить пароль в логи/чаты/команды без нужды;
  - не добавлять файл в git/бэкапы наружу;
  - если безопасность важнее — удалить файл (`rm ~/.sudo_password`) и работать вручную, либо выдать агенту NOPASSWD через sudoers.

## NOPASSWD-альтернатива (если решат убрать файл пароля)
```bash
sudo sh -c 'echo "evgeniy ALL=(ALL) NOPASSWD:ALL" > /etc/sudoers.d/evgeniy'
```
Это было предложено как более безопасный вариант, пользователь выбрал файл пароля. Решение можно пересмотреть.

## UFW
- INPUT policy **drop**; открыты: `<ssh-порт>/tcp`, `22/tcp`, `tun0` (для sing-box), исходящие 53/443.
- `3000/tcp` — DENY (сознательно, для какого-то сервиса).
- Правило `allow in on tun0` **не удалять** — без него VPN мёртв ([[Networking-Troubleshooting]]).
- sing-box НЕ открывает портов наружу: только локальный socks на 127.0.0.1 при тестах.

## Приватные данные в проекте
- `sub_url` — приватный URL подписки (ключ доступа). Не публиковать.
- `cache/*` содержит полные UUID/ключи узлов. Не коммитить/не шарить.
- `configs/singbox-last.json` и `/etc/sing-box/config.json` — содержат uuid/pbk/sid узлов. Относиться как к секретам.

## Права
- Файлы проекта принадлежат `evgeniy`. Системные (`/etc/sing-box`, сервис) — root.
- Сервис sing-box работает от root c ограниченными capabilities (CAP_NET_ADMIN/BIND_SERVICE/RAW, NoNewPrivileges=true).

## Риски
- **fail-closed:** выбранный мёртвый узел = нет интернета до переключения (см. [[Architecture]]).
- Подписка/узлы во владении третьей стороны (hy100.su) — весь egress трафик проходит через их серверы. Учитывать для чувствительных данных.
- TUN глобально на хосте с Docker — при неаккуратной правке можно задеть сеть контейнеров; держи stop-скрипт под рукой.
